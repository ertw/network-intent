## Behavior delivered

Read-only assurance panel on `/#/assurance-panel` using frozen `AssurancePanelProps`. Plan ID and graph-version label render as supplied strings with no numeric conversion; nulls display **No plan** and **Unknown graph version**. The demo fixture uses the large-looking id `9007199254740993`, which must remain exact (`Number(...)` would become `9007199254740992`).

One row per supplied input, in order, showing label, primitive token, outcome, freshness, and completeness. Null outcome is **No observation**. The eleven outcomes keep distinct labels (Timeout is not merged with Violation or Unsupported). Selecting a row calls `onSelect(id)` only; highlight follows `selectedId`. Detail shows observation source, provenance source, endpoint or **Device-local / no endpoint supplied**, supplied detail text, outcome, freshness, completeness, missing, reason, collected/received timestamps (verbatim, **Unknown** when null), and dependency IDs in supplied order. Differing source labels and dates are not reconciled.

Stale, unknown, partial, and unavailable provenance remain visible next to a raw Success outcome. A positive accent is applied only when outcome is success and the supplied freshness is fresh and completeness complete. Empty rows show **No assurance observations**. Unknown `selectedId` produces an empty detail region (no invented row). Strings render as text, not `{@html}`. Rows are keyboard-activatable buttons with the harness 3px focus ring. The panel does not display aggregate **Healthy**, **Admitted**, **Verified deployment**, or **Safe to apply**, and does not count streaks, traverse the DAG, calculate freshness, run probes, or create incidents.

## Limitations / Astra decisions

1. **Primitive display names are not in the contract.** Rows show the supplied primitive tokens (`tcp_connect`, `udp_dns`, …) rather than invented human labels.
2. **Outcome `unavailable` and completeness `unavailable` share a word.** They are distinguished only by the Outcome vs Completeness field labels. The contract has no separate display strings.
3. **Empty missing lists and null reasons have no contract placeholder.** The panel shows `none` as a UI empty marker. Null timestamps use **Unknown**, as specified.
4. **Unknown `selectedId` has no contract message.** Detail is omitted rather than inventing a row or an error string.
5. **Positive accent is display styling derived from supplied outcome + freshness + completeness**, per the packet. There is no trusted-success or health field to read. This is not an admission or deployment decision.
6. **`dependsOn` values are opaque IDs.** The panel prints them in order and does not resolve, traverse, or label the DAG.
7. **FullPage screenshots are taller than the named viewport.** The 390-wide capture is 4411px tall because `fullPage: true` includes the whole row list. Narrow overflow was still measured at viewport 390×844.
8. **Harness/demo copy mentions “admission” only as a negation** (“no … admission decisions”, “does not admit”). No aggregate Healthy/Admitted/Verified deployment/Safe to apply verdict is shown.
