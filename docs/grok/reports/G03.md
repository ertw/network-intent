## Behavior delivered

Controlled `ViewControls` at `/#/view-controls` (discovered from `Demo.svelte`). Props are the frozen `ViewControlsProps` only.

- Primary layer radios are L1, L2, L3, L4, L7 in that order. L5/L6 are not rendered.
- Advanced starts collapsed. Expanding it shows overlay checkboxes (current primary omitted, canonical order) and a Combined overview switch.
- Changing primary preserves state/assurance/edit/combined and remaining overlays. The new primary is removed from overlays. The previous primary is not added automatically.
- Combined overview true disables primary radios and overlay checkboxes while leaving those values in `value`. Combined remains enabled so it can be turned off; turning it off restores the retained primary and overlay membership.
- State view radios (Intent / Device configuration / Operational / Compare), Assurance overlay, and View/Edit are independent of each other and of layer choices.
- Every user change calls `onChange` with a new object and a new overlays array. Incoming `value` / `value.overlays` are never mutated. The demo always passes a frozen copy. There is no `$effect` that writes back `value`; mount and external Demo replacements do not emit.
- Overlay arrays on emit are unique, exclude the current primary, and follow L1, L2, L3, L4, L7. Incoming duplicates or a primary-in-overlays fixture are displayed without an automatic callback; the next emit canonicalizes them.
- Empty overlays is the default fixture. Combined overview is the read-only layer-lock case. This contract has no error/stale/freshness channel; none was invented.
- View/Edit only requests `editMode`. Visible copy states it does not authorize compiler, graph, source, adoption, or deployment operations.
- Native labelled radios, checkboxes, and switches; 3px `:focus-visible` from existing `app.css`; wrapping layout aimed at 390px without horizontal scrolling.
- Demo is labelled **DEVELOPMENT FIXTURE — NOT LIVE DATA** / SYNTHETIC. It owns the in-memory value, fixture selectors, reset, and event log. No fetches, localStorage, IndexedDB, credentials, or live device data.

## Limitations / Astra decisions

1. **Overlay canonicalization on every emit.** Primary and overlay edits always emit unique canonical overlays excluding the current primary. Other field changes go through the same `emitSelection` helper, so a state/mode/assurance/combined emit also drops duplicates and a primary-in-overlays entry rather than copying the raw incoming array. Combined overview still retains overlay *membership* (and primaryLayer) while locked. If Astra wants unrelated emits to preserve duplicate/out-of-order overlay arrays exactly, that is a one-helper change; membership retain/restore is already covered.
2. **Control types.** Exclusive choices use native radios (primary, state, View/Edit). Combined overview and Assurance overlay use native checkboxes with `role="switch"`. Advanced uses `details`/`summary`, collapsed initially.
3. **No graph/authority behavior.** The component does not filter a graph, authorize edit, fetch, or keep hidden domain state. Incomplete incoming props are not defaulted via `onChange`.
4. **FullPage screenshots are taller than the named viewport.** Playwright `fullPage: true` records document height (for example 390×2148). Narrow-width wrapping and overflow were still checked at viewport 390×844.
