## Limitations / Astra decisions

1. **Node 23 vs package engines.** Tested on Node `v23.11.0`. Vite 8 allows it (`>=22.12.0`). `@sveltejs/vite-plugin-svelte@7.3.0` engines are `^20.19 or ^22.12 or >=24`; `vitest@4.1.11` engines are `^20 or ^22 or >=24`. Both warn `EBADENGINE` and omit odd-numbered 23. No peer dependency was forced. Decision: keep testing on the host Node 23, or switch the lab to 22/24 to match nested engines.
2. **npm 10.9.2 + Vitest 4/5 `npm install` crash.** Fresh `npm install` of `vitest@4.1.11` or `vitest@5.0.1` dies in arborist (`Cannot read properties of null (reading 'edgesOut')`) while walking optional `@vitest/browser-playwright` → `msw` peers. Workaround used once: generate the lockfile with `--legacy-peer-deps`. Resulting tree has **no invalid peers** (Vitest 4 requires Vite 6, 7, or 8; we have 8.3.0). Subsequent `npm ci` works **without** that flag. Vitest 5 was not kept. Decision: accept Vitest 4.1.11 + lockfile/`npm ci`, or bump npm past 10.9.2 if a later worker needs Vitest 5.
3. **Second test fixture.** `harness-discovery` is a labelled development fixture so a second glob match is real, not only a unit-test map. G03–G08 product components were not added. Decision: keep it as a canary or delete it after G03 lands a real second `Demo.svelte`.
4. **TypeScript 5.9.3, not 6.** Current Vite svelte-ts template lists TypeScript ~6. svelte-check 4.7.6 accepts both. 5.9.3 is the locked, tested compiler.

No new presentation/domain model was invented. `@xyflow/svelte`, `elkjs`, and CodeMirror 6 packages are installed for later tasks and are not imported by the harness.
